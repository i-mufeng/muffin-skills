# 视觉设计原则

本参考把用户提供的“UI 界面优化 35 个小妙招”归并为可执行原则，并补上使用边界。选择能解决当前问题的手段，不要为了覆盖清单而添加效果。

## 1. 配色与层级

- **控制颜色角色**：可用 60% 中性/主色、30% 辅助色、10% 强调色作为探索起点，但最终应落到 `surface`、`text`、`border`、`primary`、`success`、`warning`、`danger` 等语义 token。避免各占相近面积导致竞争。
- **颜色不是唯一编码**：状态和图表同时使用文字、图标、形状或纹理。高饱和色集中在动作、状态和少量重点，不铺满整页。
- **明确优先级**：同一区域通常只放一个主按钮。次要动作用弱填充、描边或文本按钮；危险操作与主动作在颜色、位置和确认机制上区分。
- **层级先于装饰**：按重要性调整顺序、字号、字重、对比、位置和留白。仅显示完成任务所需信息，把次要细节渐进披露，而不是无差别列成表格。
- **减少分隔线**：优先用间距、分组、背景层级和对齐分隔内容。保留对理解表格结构、边界或交互状态确有帮助的线。
- **视觉对齐而非只看几何值**：圆形、图标及 A/C/O/Q/S/T/V 等字形会产生光学偏差；必要时微调，但保持布局基线可解释。

## 2. 字体与内容

- **建立小型字阶**：正文、辅助文字、小标题、页面标题各有稳定的字号、行高与字重；同层级不随意变化。正文通常从约 `1.4-1.7` 行高开始，再按字体与密度校准。
- **优先可读字体**：正文避免装饰性强、字形易混淆或过细的字体。字体选择服务于产品语气，也要包含需要的中文、拉丁、数字和符号字符。
- **按文字系统回退**：中英文可以使用协调的不同字体，但用一个有序的 `font-family` 栈自动覆盖，不要逐片文本手工切换造成基线和字重混乱。
- **增强图片上的文字**：先选择留有安全区的图片和合适裁切；仍不足时使用稳定的局部遮罩、实色底或渐变蒙版。逐行加碎片化底色只适合明确的视觉语言。
- **文本对齐遵循阅读关系**：正文和列表通常左对齐；数字表格按小数位或右对齐；标签与值保持可扫描关系。不要为“整齐”破坏自然阅读顺序。
- **真实内容压力测试**：测试长标题、长英文单词、中英文混排、大数字、空值、多行说明和本地化。用换行、截断加完整内容入口或弹性布局处理，不允许静默遮挡。

## 3. 空间、形状与卡片

- **使用间距尺度**：采用少量重复间距值，并让组内间距小于组间间距。所谓“双倍间距”只是表达亲疏关系的一种起点，不是固定比例。
- **给信息呼吸空间**：留白承担分组与强调，但运营后台、表格和高频工具应保持适当密度，不能为追求“高级感”牺牲扫描效率。
- **卡片有明确语义**：适合可重复条目、选择项、独立对象或边界明确的工具。定价/方案选择可把整张卡设为选择目标，状态必须清晰且可键盘操作。
- **避免卡片套卡片**：嵌套边框和阴影会制造虚假层级。内部用标题、分组、分隔或背景轻微变化表达结构。
- **圆角体现嵌套关系**：内层圆角通常不大于外层，并结合实际内边距计算视觉关系。统一使用有限的半径 token，不把“外层一定是内层两倍”当硬规则。
- **阴影不是纯黑**：需要抬升时使用低透明度、较大模糊和与背景协调的色相；暗色模式单靠阴影常无效，应配合边框或色面。避免每个容器都悬浮。
- **背景效果有理由**：纹理、几何形、柔和渐变或毛玻璃只能用于加强品牌、景深或内容区分。毛玻璃必须有可用的纯色降级，并检查文字对比与渲染成本。
- **叠加建立关系**：头像跨越封面、徽标叠在对象等手法可建立归属，但要预留裁切、描边和点击区域，避免元素遮挡关键信息。

## 4. 控件与图标

- **整块可点击**：选择卡、列表项和带图标动作的可点击区域覆盖完整视觉目标，不让用户只能点小圆点或小图标。
- **优先可辨识按钮**：只有在图标含义高度通用且上下文明确时使用纯图标按钮；否则用图标加文字。陌生图标提供可访问名称和 tooltip。
- **图标保持一致**：同组使用同一套图标，统一视觉尺寸、描边粗细、端点、填充方式和容器。不要通过任意加底座补偿大小差异，应先统一 viewBox 与光学尺寸。
- **形状传达角色**：主入口可使用圆形、超椭圆或其他品牌形状，但交互含义和选中状态要比造型更明确；熟悉的平台模式优先。
- **选项数量决定控件**：少量互斥选项可用 radio、segmented control 或 swatch；选项多、文字长或空间有限时用 select、combobox 或分步选择。阈值取决于可扫描性，不机械套用“5 个/7 个”。
- **表单分组而非满屏框线**：标签长期可见，相关字段成组，错误紧邻字段，必填规则一致。不要只靠 placeholder 充当标签，也不要用大片分隔面掩盖结构问题。

## 5. 图片、数据与状态

- **图片承担真实信息**：产品页展示可检查的实物/界面/场景，而不是模糊氛围图。保证合适的宽高比、焦点裁切、`alt` 文本和加载失败布局。
- **图表匹配问题**：比较用条形图，趋势用折线图，组成关系谨慎用堆叠或饼/环图；精确值仍提供文本。类别颜色须可辨，图例靠近数据，避免 3D 和装饰性数据墨水。
- **单个指标不滥用图表**：进度环只在“部分/整体”关系或进度感本身重要时使用；否则清楚的数字和单位更快。
- **空状态解释下一步**：区分首次使用、筛选无结果、权限不足、离线、错误和真正为空。说明发生了什么，并在有可恢复动作时给出一个明确动作；插画是辅助，不是必需。
- **反馈靠近动作**：加载、成功、错误、禁用和选中状态位置稳定。异步操作防止重复提交；错误信息说明如何恢复；重要结果不能只用 toast 瞬间提示。

## 6. 对参考图技巧的校正

下列技巧可能有效，但不能设为默认规则：

- 60/30/10 是配色启发式，不是可访问性或品牌一致性的保证。
- 毛玻璃、渐变、背景装饰和元素叠加是风格手段，不天然“更高级”。
- 卡片、圆形入口和图表只有在语义匹配时才改善体验。
- “减少文字”“只显示重要信息”不等于隐藏关键条件、价格、风险或错误原因。
- “优先使用按钮”不等于把链接、导航或切换器都做成按钮；语义 HTML 和预期行为必须匹配。
- 字体、圆角、间距的倍数关系应由 token 和内容验证决定，不应用单张示例推导普遍定律。
