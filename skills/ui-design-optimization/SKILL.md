# Vue 界面设计与组件复用

让界面有明确的产品性格、清晰的操作层级，以及可以直接继续开发的 Vue 源码。漂亮截图、通过构建、真实业务接入是不同证据，分别说明。

## 先判断交付类型

- **已有 Vue 项目**：先读取项目约定、Vue 入口、相邻页面、组件、token 和包版本。沿用现有设计系统、命名和组件库；不要另搭 React 项目或覆盖已确认的视觉基线。
- **新 Vue 设计稿**：默认 Vue 3 SFC + TypeScript + Vite；Nuxt 或其他项目已有栈优先。设计稿包含可操作页面、可复用组件和独立组件展示入口，使用本地样例数据。
- **只评审截图/讨论**：输出按影响排序的具体建议，不擅自生成工程。原 35 条技巧仅作补充，见 [ui-design-tips.md](references/ui-design-tips.md)。
- **只在 ChatGPT 文本环境中**：交付完整文件结构和 `.vue` 源码、运行命令及待验证事项；不能声称已运行。具有文件与浏览器工具时实际落盘、编译、操作和看截图。不要依赖特定宿主的 `show_widget`、React artifact 或 CDN Vue。

## 工作流程

以下源码实现流程适用于实现任务；局部优化只执行相关步骤，不额外创建页面、展厅或整套主题。只评审截图时区分可见观察与待验证假设。

1. **确定主任务与视觉方向。** 用一句话说明为谁解决什么问题，再选定推荐方向及关键取舍。参考素材提炼布局、色彩、排版与节奏，不抄布局皮肤。常规缺省自行决定；只有不同理解会改变主要产出时提问。
2. **先做一个代表性纵向切片。** 选一个核心页面及主交互，用真实长度中文、可信样例和失败状态建立可评审基准；不要先堆十个同质空页面。若用户要求分步确认，就在约定节点停下；否则完成当前授权范围。
3. **确立色彩与基础 token。** 配色前读 [color-system.md](references/color-system.md)，明确品牌、中性、状态、图表角色。新项目默认 1 主色 + 0–2 辅助强调色，绝非全部 HEX 总数上限。既有系统优先；数值来源分“标准要求”和“技能建议”。
4. **把视觉与交互沉淀为组件。** 实现前读 [vue-components.md](references/vue-components.md)。基础组件管表现和行为，业务组件管领域含义，页面管组合与数据。复用通过 props / emits / slots / composables 实现，不复制整页，不用大量布尔开关制造万能组件。
5. **做出产品性格。** 通过内容结构、对齐、字体尺度、密度、留白、色温和必要媒体形成辨识度。业务工作台首屏直接呈现工作；避免营销大标题、彩虹 KPI、无意义卡片嵌套和大段实现说明。图标优先已有库，陌生操作保留可访问名称及必要文本。
6. **验证并定点修正。** 按 [delivery-and-review.md](references/delivery-and-review.md) 走主流程和失败路径，真实查看桌面/手机截图。先修阻断、层级、溢出，再修视觉细节；达到当前验收后停止，不自行扩展全站重构。

## 复用必须能证明

- 所有抽取出的 UI/业务组件有明确输入输出，可脱离原页面使用；页面自身允许负责路由与数据，不要求每个 `<div>` 单独组件化。
- 基础组件不访问业务接口、路由、全局 mock 或页面私有 store。支持主题、适用状态和内容变化；复杂组件优先既有成熟实现。
- 页面与组件展厅导入同一源码；新增共享组件至少用两组内容或状态验证，关键组合在不同业务上下文中验证。不能用截图、复制代码或改名副本充当复用。
- 原生语义、标签关系、键盘、焦点、受控状态属于组件能力。可访问性不能留给每个页面重新补。

## 最终交付

仅截图评审时交付观察、推断与待验证建议，不声称运行、键盘或精确色对已验收。实现任务则提供 Vue 源码/预览入口、可复用组件及用法、token 与配色理由、关键状态、实际运行结果和未验证项。设计约定写进项目文档，不放入面向用户的产品页面。按现有项目授权处理发布，不把本技能视为部署或付费调用授权。
